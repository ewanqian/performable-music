## INFERENCE — why this matters to Performable Music

The useful lesson is not “complex technology = advanced music.”

It is:

> Design a small, inspectable rule system that can generate complex musical behavior while remaining playable, repeatable and connected to physical experience.

The strongest transferable ideas:
- complex rhythm controlled by a few meaningful variables;
- mathematical functions as compositional material;
- deterministic event/state data as a shared source for sound and image;
- body/gesture data interpreted semantically rather than mapped raw to every parameter;
- agents proposing plans while deterministic systems execute them;
- club-music physicality preserved even when the generation logic is abstract.

## MECHANISMS TO EXTRACT

### D01 — Two Clocks
Two rhythmic systems with rational relations: 4:3, 5:4, 7:4. Performance controls change ratio, density or crossfade.

### D02 — Preview / Commit / Render
Every generated idea has:
- parameter state;
- quick audition;
- named preset;
- deterministic render.

### D03 — Function Music
Represent pitch/gate/filter/density as bounded functions, then let the performer alter function parameters.

### D04 — Shared Event State
One event/state representation drives:
- audio;
- visual;
- spatial behavior;
- logs/replay.

### D05 — Agent Plan, Human Approval
Agent generates A/B/C structural plans. Human listens, selects, edits and performs.

## PRACTICE TASK

Create a 60-second process study:
- 2 clocks;
- maximum 5 sound sources;
- one ratio parameter;
- one density parameter;
- one event reset;
- one visual mapping from the same state.

The study must be repeatable from saved parameters.
