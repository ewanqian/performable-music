# 第一轮 Demo 代办：四个音乐候选，三个视觉实验

2026-11-18 · 归属 [The Point 双机制作](README.md) / [主任务 #57](https://github.com/ewanqian/performable-music/issues/57)。本文件是下一轮有边界的制作目标，不是音频、视觉或现场已完成的声明。

## 本轮最高优先级

**得到两种确实不同、能够现场控制的音乐，再让同一个视觉场景跟随它们演奏。**

探索上限：四个音乐候选席位，包含现有复苏；三个15–30秒视觉实验，共用已有场景。制作上限：只把试听选中的两种音乐做成60–90秒可演奏段，选一个视觉方案完成两段音画和一次转场。交付一段连续演示，目标约三分钟，按自然段落合计约2分15秒–3分30秒，不为凑时长复制内容，也不等于30分钟演出已经完成。

这次扩大的是作曲方式的选择范围。新音色、换混响或同一结构换预设，不自动算新的音乐类型。既有素材能占候选席位时直接复用，不额外堆第五首。

## 1. 音乐清单：四个席位，只深化两个

这些是作曲方向提案，非对尚未听到的音频做分类。以Mac现有DAW owner顺序制作/整理，保护实际复苏和AMB源。

| ID / 方向 | 具体听觉目标与作曲方法 | 第一份交付 | 后续控制问题 | 不通过的典型情况 |
| --- | --- | --- | --- | --- |
| M0 · 复苏基线 | 保留当前作品身份与真实编排，确定其最值得发展的片段 | 现成45–60秒对照及源版本；可直接保留原110秒文件另标试听区间 | 一项真实可控的音色/层次变化是否听得见，并能释放、继续 | 借整理任务重做整首；伪称发行版已通过现场控制 |
| M1 · 触击 / 切分与低频问答 | 以短而有触感的打击句、明确停顿和低频回答推进；少量声部让节奏句清楚。与复苏比较时，重点是更明确的问答和句法 | 45–60秒，包含一个可记住的节奏句、一次发展和一次留白/释放 | 一个连续量改变密度或音色触感；按住/释放能进入或退出回答声部 | 只有同一MIDI换音色，或与复苏的碎片节奏听起来同构 |
| M2 · 漂移 / 颗粒与环境空间 | 从可辨认的源声音走向颗粒聚散、近远和材质变化；音色过程本身组织时间，留下安静处 | 45–60秒，源声音出现、一次可听转化、余响结束 | 一个连续量改变颗粒/距离；按住累积、释放回到可保持的状态 | 只是给同一循环加大混响；无发展长轰鸣、持续刺耳或完全不可复现的随机 |
| M3 · 回返 / 动机与和声 | 一个能辨认的短动机，在不同和声或声部关系中回来；以情绪发展连接空间，乐器由现有合适声源选择 | 45–60秒，主句、改变后的回返和结尾；不要强制钢琴或预设调性 | 一个连续量展开声部/材质；保持与释放后主句仍可辨认 | 单调琶音器循环、玩具感旋律、只有加层加响而无音乐关系变化 |

R0的70.3秒剪辑版先试听，再由艺术家决定是否占M1或M2等某一席；占位后相应任务是补足/改进，不另做重复草稿。保留其团队来源，不能改署名为个人原创。若与现有席位重叠，它仍是素材和参考，不扩大本轮候选数。

### 每个音乐草稿的完成定义

- [ ] 一段真实可听的文件，至少能指出“开始、一次变化、结束或可接续尾部”。
- [ ] 一句话说明它与M0的作曲差别，附至少一个时间码。不能只写风格标签。
- [ ] 可继续编辑的实际工程/片段，以及声源、作者和处理来源。
- [ ] 同一监听音量下比较；需要响度匹配时另存试听副本，不覆盖原母带。没有视频辅助也值得继续听。
- [ ] 作者给出 KEEP / REVISE / REJECT。首轮最多保留两项深化，其中至少一项来自新增方向；如果没有新的值得保留，只修最有潜力的一项，不继续扩候选数量。

本轮先比较M0与M1，再做M2/M3的短声音草稿。M0/M1明显重叠时先改变作曲机制或淘汰M1，不用名称凑满四种。

## 2. 控制清单：先两个操作，选中后最多三个

首个控制证明用现有键盘/MIDI设备完成，沿用现有Show Score与交接。手部/XR接入放在音乐和基础控制通过之后。

| 操作 | 一致的演奏含义 | 各音乐可采用的映射 |
| --- | --- | --- |
| 连续量：展开 | 从较克制到较展开，声音仍保持身份；不直接当master音量 | M1密度/触感；M2颗粒/距离；M3声部/材质；M0依据实际工程选择 |
| 按住／释放：介入 | 按住进入一个有边界的变化，松开后按已设计包络回到可继续演奏的状态 | 回答声部、颗粒累积、纹理或伴随声部；不是每次都必须瞬间静音 |
| 段落推进：NEXT（只给最终两项） | 在作者选定的乐句边界进入下一状态 | 共用既有cue语义；不为每首写新控制框架 |

- [ ] 对选中的每一段连续做三次“介入—变化—释放”，记录实际音频与输入；声音可辨、无卡住的持续音。
- [ ] 连续量有明确起止范围，松手后仍能继续；相同操作在两段音乐中保持相同含义。
- [ ] 可从中段停止、回到起点重新开始；既有停止/静音机制继续独立可用。
- [ ] 操作确实改变声音后，再让同一个事件改变灯光、扫描或HUD。仅亮了按钮或画面闪烁不算音乐控制通过。
- [ ] 实测BPM/拍号、真实MIDI与人工cue的来源清楚；不把音频推测值写成原工程数据。

## 3. 视觉清单：三个短实验，共用现有资产

| ID / 优先级 | 具体做什么 | 基础完成标准 | 已有基础与范围 |
| --- | --- | --- | --- |
| V1 · 石体显影 / 必做 | 选现有Boulder与Reactor恢复效果的最佳灯态；做顶/底或左右一次清晰转换，再做一次扫描显露 | 15–30秒；静帧材质与空间成立；绑定至少一个正式音乐事件；标明消费音乐版本 | 已报告15秒离线片与三灯态，先审阅再增量改，不从零重建 |
| V2 · 空间HUD / 第二顺位 | 在同一场景加一组空间标记，完成出现—锁定/跟随—收束三个动作；只读真实cue/对象状态 | 15–20秒；三个状态各有可读变化；共用一个实际事件入口；不遮住主体 | 使用现有机位/资产；最多一组标记，不扩成完整科幻桌面或控制平台 |
| V3 · 身体留痕 / 探索项 | 用已报告的排练动作关节代理，选一个伸手/侧移动作，表现石层迟滞与一处残留 | 15–20秒；关闭闪烁后仍看懂动作和后果；准确标为代理/缓存或实际输入 | 有现成动作代理，但未证明成片质量；不新搭全身动捕或高精数字人。若短实验仍看不懂，后排，不阻塞音乐 |

三个是候选试验，不要求三个都进入演出。先保住V1，V2可以成为同一视觉中的独立层；V3只进行一轮、最多45分钟的动作映射实验，到时交当前结果或明确后排，不影响工作段C。最终基础交付只要求一个被选中的主视觉系统。

## 4. 顺序与最低交付

### 工作段A：先得到可判断的声音与画面

- [ ] Mac给M0参考段；Windows给R0试听和V1现成样片。
- [ ] 听M0/R0，记录原材料身份；决定R0是否占候选席位。
- [ ] Mac做M1或改进已占位的R0；先交短声音，已有工程可顺手验证一项控制，接线障碍不拖住其他音频草稿。
- [ ] Windows只针对V1选定画面改进，并按Mac包对齐，不新增大场景。

### 工作段B：补足差异，停止扩张

- [ ] Mac分别交M2/M3短声音；如已有候选覆盖其中一席就复用。
- [ ] 四个席位做一次纯音频比较；选两项，不默认四项都深化。
- [ ] Windows完成V2短实验；V3只用现成动作代理做一次有限试验。

### 工作段C：把选中的东西演奏出来

- [ ] 两段各60–90秒音乐具有上述控制，并可重新打开实际工程。
- [ ] 同一个选定视觉分别跟随这两段音乐；至少各有一次真实输入的音画后果。
- [ ] 做一次15–30秒转场，明确前段怎样退出、后段怎样进入，不靠全黑掩盖全部衔接。
- [ ] 一次连续录下两段与转场，约三分钟；交音乐包、控制记录与视频版本关系。
- [ ] 艺术家分别判断声音、画面和操作；记录保留与要修改的位置。

### 本轮“基础完成”勾选

- [ ] 最多四个席位已完成试听比较，至少两种具有明确差异的音乐被选中。
- [ ] 两段音乐真正可控；至少一段来自新增方向。
- [ ] 一个主视觉被选中并与两个音乐版本对齐。
- [ ] 一段约三分钟连续音画、一次明确转场、实际工程可重开。

通过后再把这两种音乐发展成6–8分钟连续排练单元，再规划覆盖提案中的完整演出时长。三分钟证明、6–8分钟单元和30分钟节目是不同阶段，不互相冒充完成。

## 5. 本轮先后排的事项

第二代复杂反应堆、完整雨林/月球世界、新AI短片批次、素材采购、超高分辨率全片、全身实时动捕、另写引擎/控制台都先留候选。保留已有研究，不同时开工。

暂停新增任务的判断：一项工作若不能帮助“听出新音乐差异、证明控制、改善入选主画面或完成这次交接”，本轮先后排。宏大概念保留在原方案，制作人员只领取本清单的下一项。

## 6. 职责与状态

Mac当前唯一DAW owner负责M0–M3及最终音乐包；Windows Renew继续已领取视觉资产工作和V1–V3。Windows已有R0是临时参考与可选材料，不因存在它而增加第二位正式编曲负责人。

本清单没有启动本机进程。M0有既有作品，R0/V1有本地执行报告但艺术审阅待补；M1/M2/M3是待制作或待归位候选，V2/V3是待审阅/制作实验，不能预勾完成。提交输出时沿用 [回执模板](RECEIPT.template.json)；任务摘要归#57，私有视觉证据归Atmospheric Escape #13。
