# Phase 01 Performance — 2026-12-03

## Objective

Present the first complete **Performable Music** system as a coherent interactive album/live set.

This is not a showcase of twelve disconnected demos. It should feel like one musical world with a clear arc and a small, legible performance grammar.

## Working structure

### ACT I — SEED / ORIENTATION
Introduce pulse, tonal identity and the simplest interaction.

### ACT II — EXPANSION / SYSTEM
Reveal multiple clocks, layers, cuts and generative relationships.

### ACT III — MUTATION / PEAK
Use space, history, Agent-produced plans or spectral instability to transform the established system.

### ACT IV — RELEASE / AFTERIMAGE
Reduce system complexity and return to a memorable harmonic/melodic field.

## Minimum repertoire

Select 3–4 final systems from the 12-mechanism pool.

Required roles across the set:
- one piano/electronic piece;
- one rhythmic/process piece;
- one spatial/gesture-driven piece;
- one Agent-assisted structural experiment.

A single piece may satisfy more than one role.

## Performance inputs

Priority:
1. foot / button / MIDI for reliable explicit state changes;
2. hand / spatial gesture for continuous expressive controls;
3. optional Vision Pro / WebXR where stable;
4. future EMG branch, not required for this deadline.

## Output modes

### Showcase
12–20 minutes. Designed for festival application, documentation, demos and short-stage slots.

### Full
25–45 minutes. More room for build/hold/variation and performer decisions.

### Installation / autonomous mode — later
A subset of the music system may run generatively with bounded visitor input. This is not required for Phase 01 but should influence architecture.

## Festival-ready package to create after the music works

- 80–120 word concept;
- 1 sentence system explanation;
- 60–90 second trailer;
- 5 minute documentation excerpt;
- stage diagram;
- input/output/tech rider;
- fallback mode;
- performer photo / system screenshots;
- public repository research link;
- clear credit / acknowledgements.

## Freeze

By 2026-11-29, avoid adding new core technologies. After that date, prioritize rehearsal, transitions, sound balance, documentation and failure recovery.
